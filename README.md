# CampusLife — мобильная афиша мероприятий школы/кампуса

Решение кейса трека «Мобильная разработка» Всероссийского хакатона TASKILLS.

**Проблема.** Информация о школьных мероприятиях, кружках и конкурсах разбросана по чатам, объявлениям и сайтам, анонсы теряются — из-за этого сообщество хуже вовлекается в жизнь школы, а организаторы недополучают участников.

**Решение.** Мобильное приложение, где все события собраны в одном месте, доступны по интересам и датам, а запись, билеты и напоминания помогают не забыть о выбранном событии.

---

## Функционал (соответствие заданию трека)

### 1. Лента мероприятий
- Вертикальная лента событий в стиле TikTok: фото и короткие видео, название, дата, время, место, краткое описание.
- Карточка события открывается по нажатию — подробное описание, кастомные поля анкеты, контакты организатора, счётчик мест, действие «Записаться / Отменить».
- Анимированный фон-океан, фильтр «рыбок», светлая и тёмная темы.

### 2. Фильтрация и поиск
- Поиск по названию, описанию и месту проведения.
- Фильтр по 8 категориям: спорт, творчество, наука, конкурсы, лекции, музыка, волонтёрство, выезды.
- Выбор диапазона дат, сброс всех фильтров одним действием.

### 3. Запись на мероприятие и билеты
- Запись через форму с динамическими полями (текст, число, ссылка, да/нет, выбор из списка), обязательные поля проверяются сервером.
- Раздел «Мои билеты» в профиле: все записи участника с **актуальным статусом** — «На рассмотрении», «Одобрено», «Пришёл», «Отклонено».
- У каждого билета QR-код; организатор видит количество записавшихся и графики статистики (заявки по дням, посещаемость, заполненность).

### 4. Избранное и напоминания
- Добавление/удаление в избранное сердечком в ленте и в карточке.
- Раздел «Избранное» в профиле.
- Напоминания: за час, за день или в произвольное время; настройка и сброс напоминания прямо из избранного.
- Избранное и напоминания хранятся **на сервере** и синхронизируются между устройствами.

### Усложнение: события организатора и QR-проход
- 6-шаговый мастер создания события: афиша → время и место → медиа → анкета на вход → проверка → публикация.
- Загрузка фото/видео, предпросмотр, черновики и отправка на проверку модератору.
- Кабинет организатора: свои события со счётчиками заявок, разбор анкет (одобрить/отклонить), заявки на вступление в команду, статистика.
- **QR-проход**: билет участника содержит код `eventId:userId`, организатор сканирует его камерой (или вводит вручную на web) — отметка о проходе попадает в статистику. Отдельный QR используется для шаринга события.
- Панель администратора: модерация событий, ключи приглашений, управление пользователями/организациями, разбор жалоб.

### Дополнительно
- Интеракционный онбординг с симуляцией ленты и заданиями.
- Deep link `/events/<id>` — ссылка из шаринга открывает нужную карточку события.
- Валидация ключей приглашения организатора (`CL-XXXX-XXXX`), хеширование паролей PBKDF2, Bearer-токены, роли.

## Архитектура

| Компонент | Технологии |
|---|---|
| `campuslife_app/` | Flutter / Dart, Riverpod, Drift (SQLite), `qr_flutter`, `mobile_scanner`, `fl_chart`, http |
| `campuslife_server/` | Python 3.10+, стандартная библиотека, SQLite (WAL), PBKDF2-HMAC-SHA256, Bearer-токены |
| `campuslife-data/` | Данные сервера (SQLite) |
| `ascii-sharks-site/`, `CampusLife.html` | Дизайн-прототип экрана входа с анимацией океана (TypeScript, Canvas) |
| `deliverables/` | QA-скриншоты экранов |
| `tool/` | Скрипты сборки, QA и генерации демо-медиа |

Слои приложения: `app` (роутинг, DI, темы) / `domain` (сущности и интерфейсы репозиториев) / `data` (локальный Drift-репозиторий и серверный репозиторий) / `presentation` (экраны).
`ServerRepository` расширяет локальный репозиторий: авторизация, события, заявки, медиа, избранное, напоминания, билеты и QR-проход идут через API.

## Запуск

### 1. Бэкенд

Из корня репозитория:

```bash
py -3 -m campuslife_server.server --port 8080
```

Сервер поднимет API на `http://127.0.0.1:8080`, создаст/проинициализирует БД в `./campuslife-data` и засеет демо-аккаунты:

| Роль | Email | Пароль |
|---|---|---|
| Участник | `student@campus.ru` | `password123` |
| Организатор | `organizer@campus.ru` | `password123` |
| Администратор | `admin@campus.ru` | `password123` |

Рабочие ключи приглашения для регистрации организатора: `CL-CAMP-2026`, `CL-DEMO-ORGS`, `CL-HACK-2026`.

Демо-Верификация (email/SMS) в интерфейсе использует код `0000` — это симуляция для демонстрации, не реальная отправка сообщений.

### 2. Клиент (Flutter Web)

```bash
cd campuslife_app
flutter pub get
flutter run -d chrome --dart-define=CAMPUSLIFE_API_URL=http://127.0.0.1:8080
```

Требуется Flutter с Dart `>=3.11.4 <4.0.0` (проверено на Flutter 3.41.6 / Dart 3.11.4).
Если `CAMPUSLIFE_API_URL` не задан, приложение работает на локальной БД Drift (удобно для офлайн-демо).

### 3. Проверки

```bash
py -3 -m unittest discover campuslife_server
cd campuslife_app
flutter analyze --no-pub
flutter test
```
