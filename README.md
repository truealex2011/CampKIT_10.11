# CampusLife — мобильная афиша мероприятий школы/кампуса

Решение кейса трека **«Мобильная разработка»** Всероссийского хакатона по информационным технологиям **TASKILLS**.

**Проблема.** Информация о школьных мероприятиях, кружках и конкурсах разбросана по чатам, объявлениям и сайтам, анонсы теряются — из-за этого школьное сообщество хуже вовлекается в жизнь школы, а организаторы недополучают участников.

**Решение.** Мобильное приложение, где все события собраны в одном месте, доступны по интересам и датам, а запись, билеты и напоминания помогают не забыть о выбранном событии.

---

## Выполнение задания трека

### 1. Лента мероприятий
- Вертикальная лента событий в стиле TikTok: фото и короткие видео, название, дата, время, место, краткое описание.
- Карточка события с подробной информацией: описание, кастомные поля анкеты, контакты организатора, вместимость, действие «Записаться».
- Анимированный океан-фон, переключатель рыбок, светлая и тёмная темы.

### 2. Фильтрация и поиск
- Поиск по названию, описанию и месту проведения.
- Фильтр по 8 категориям: спорт, творчество, наука, конкурсы, лекции, музыка, волонтёрство, выезды.
- Выбор диапазона дат и сброс всех фильтров одним действием.

### 3. Запись и билеты
- Запись через анкету с динамическими полями (текст, число, ссылка, да/нет, выбор из списка), обязательные поля проверяются сервером.
- Раздел «Мои билеты» с актуальным статусом: «На рассмотрении», «Одобрено», «Пришёл», «Отклонено».
- QR-код у каждого билета; организатор видит счётчик «записалось N из M» и графики статистики.

### 4. Избранное и напоминания
- Добавление/удаление в избранное, отдельный раздел в профиле.
- Напоминания за час, за день или в произвольное время; настройка и сброс прямо из избранного.
- Избранное и напоминания хранятся на сервере и синхронизируются между устройствами.

### Усложнение: создание событий и QR-проход
- 6-шаговый мастер: афиша → время и место → медиа → анкета на вход → проверка → отправка на модерацию.
- Загрузка фото/видео со счётчиком «Загружено: N/20», предпросмотр «как в ленте», черновики.
- Модерация: организатор отправляет событие со статусом `pendingReview`, в общую ленту его публикует администратор; причина отказа возвращается организатору.
- Кабинет организатора: поиск, фильтры по статусам, разбор анкет, заявки в команду, статистика.
- **QR-проход**: билет содержит код `eventId:userId`, организатор сканирует камерой или вводит код вручную; отметка попадает в статистику. Повторный проход блокируется.
- Панель администратора: очередь модерации, выпуск одноразовых ключей, управление пользователями и организациями, разбор жалоб.

### Дополнительно (сверх ТЗ)
- Интеракционный онбординг на 11 шагов с симуляцией ленты и жестов.
- Deep link `/events/<id>` — ссылка из шаринга открывает нужную карточку.
- PBKDF2-хеширование паролей, Bearer-токены, роли, проверка владельца события, лимит мест, защита от IDOR и повторного чекина.
- Анимированный океан с рыбками как фирменный стиль приложения.

## Архитектура

| Компонент | Технологии |
|---|---|
| `campuslife_app/` | Flutter / Dart, Riverpod, Drift (SQLite), `qr_flutter`, `mobile_scanner`, `fl_chart`, http |
| `campuslife_server/` | Python 3.10+, стандартная библиотека, SQLite (WAL), PBKDF2-HMAC-SHA256, Bearer-токены |
| `campuslife-data/` | Данные сервера (SQLite) |
| `ascii-sharks-site/`, `CampusLife.html` | Дизайн-прототип экрана входа с анимацией океана (TypeScript, Canvas) |
| `deliverables/` | QA-скриншоты экранов |
| `tool/` | Скрипты сборки, QA и генерации демо-медиа |

Слои приложения: `app` (роутинг, DI, темы) / `domain` (сущности и интерфейсы репозиториев) / `data` (локальный Drift-репозиторий и серверный репозиторий) / `presentation` (экраны).

`ServerRepository` расширяет локальный репозиторий: авторизация, события, заявки, медиа, избранное, напоминания, билеты, QR-проход, модерация, ключи и счётчики идут через API.

## Запуск

### 1. Бэкенд

Из корня репозитория:

```bash
py -3 -m campuslife_server.server --port 8080 --data-dir ./campuslife-data
```

Сервер поднимет API на `http://127.0.0.1:8080`, создаст/проинициализирует БД в `./campuslife-data` и засеет демо-аккаунты.

### 2. Клиент ( Flutter Web)

```bash
cd campuslife_app
flutter pub get
flutter run -d chrome --dart-define=CAMPUSLIFE_API_URL=http://127.0.0.1:8080
```

Требуется Flutter с Dart `>=3.11.4 <4.0.0` (проверено на Flutter 3.41.6 / Dart 3.11.4).
Если `CAMPUSLIFE_API_URL` не задан, приложение работает на локальной БД Drift (офлайн-демо).

Для раздачи готовой сборки:

```bash
cd campuslife_app
flutter build web --no-wasm-dry-run --no-web-resources-cdn --dart-define=CAMPUSLIFE_API_URL=http://127.0.0.1:8080
node tool/serve_web.mjs 8731
```

Клиент: `http://127.0.0.1:8731`, проверка API: `http://127.0.0.1:8080/health`.
